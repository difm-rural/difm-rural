# My Property Network V1

My Property Network is available from Home on provider web and Expo. It opens with a first-visit setup where the member picks the parts of their property, then an overview with an interactive property diagram. The List toggle exposes the same controls. The radial links show where providers are linked, and a separate marker identifies areas with a service explicitly set to **I need to find someone**.

A requester can hide and re-add areas, set each service's status, and add custom services. Hiding an area keeps its settings and linked providers. A service can link several providers from Saved, Worked together or public listing discovery. Provider profiles, category-filtered browsing, new-job drafts and invitations open through the existing workflows. Linking a provider sends no notification.

Migration `20261118170000_property_network.sql` adds owner-only tables for area preferences, service states and provider links. Suggested services are generated from the shared catalogue and only materialised when used. RLS scopes every row to its owner. Linking uses an invoker RPC, the existing public profile projection and a composite foreign key to the owner's service. Property addresses and job details are outside the data model.

## Areas and categories

There are 11 support areas. Together they reach every category in `shared/categories.ts` except General Rural Help. Each suggested service in `SUPPORT_AREAS` has a fixed `key` (`suggested-N`), its own listing `category`, and an optional `kind` (Equipment hire is kind `hire`, category `Machinery`). Find help, provider discovery and matching use the service's category and kind. Post a job uses the main category (`propertyJobCategory`). The new areas, Spraying & Pests, Hay & Feed, and House & Property Sitting, start inactive. Weed spraying moved from Pasture & Land to Spraying & Pests and kept `suggested-1`. Migration `20261118224050_property_network_more_areas.sql` widens the area checks and moves the saved Weed spraying rows and their links. It also activates Spraying & Pests for owners who had set Weed spraying up. Up to 8 active areas share one oval. With 9 to 11, the diagram uses a taller oval (`propertyDiagramRatio`). Web icons are Lucide (`property-network/area-icon.tsx`). App icons are Ionicons, with `mci:` MaterialCommunityIcons used for the tree and barley icons, which Ionicons lacks.

## Simpler setup

On a first visit (no saved area rows), the member sees **What's on your property?**: 11 tiles, none ticked. Saving stores every area in one call through `savePropertyAreas`; **Skip for now** goes straight to the overview. The overview shows the services marked Need help first, then a card per area with a status tag, a sorted / help / not-checked bar, and who covers it. The diagram is still there behind List | Diagram. In an area, each service takes one tap: Sorted, Need help or N/A. Tapping the same choice again clears it. Sorted offers an optional **Who does it?**: Me saves `self`; a member or a private contact saves `has_provider` through the existing link RPCs. Removing the last link goes back to plain `sorted`. Migration `20261120074030_property_network_sorted_status.sql` adds `sorted` to the status check. **All sorted** and **None of this applies** fill only unanswered services, and they ask first when some are already answered. The shared logic lives in `shared/propertyNetwork.ts` (`propertyServiceChoice`, `propertyChoiceStatus`, `propertyAreaProgress`, `propertyGaps`, `propertyBulkServices`).

## Private contacts

Owners can link people who are not on Rural Connections. These private contacts need a name; phone, email and note are optional. Migration `20261119022010_property_network_contacts.sql` adds owner-only `property_network_contacts` and `property_network_contact_links`. A composite foreign key keeps links on the owner's own contacts, and restrictive policies hide both tables from AI assistant tokens. Linking uses `link_property_network_contact`. **Replace with member** (`replace_property_network_contact`) links the chosen member to every service the contact covers, then deletes the contact, in one transaction. Contacts are never matched to member accounts. Invite to Rural Connections uses the device share sheet in the app. On the web it uses `navigator.share`, or copies the text when sharing is unavailable. Nothing is sent from our side. Validators live in `propertyContactFields` (shared) and match the table checks. SQL checks: `tests/sql/property-network-contacts.test.sql` (plain PostgreSQL 17, disposable database).

The post-completion suggestion is deferred. Requesters can link providers from Worked together in V1.
