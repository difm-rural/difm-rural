## Town suggestions

Mobile already uses `AddressAutocomplete` on the location step. Web uses a debounced address lookup and a separate place-details request when an exact address is selected. Its public town field is independent free text. A lightweight option is a local, curated New Zealand town and suburb list with prefix matching, capped suggestions and a free-text fallback. Select only the public town label and leave the exact address and map pin alone. Review list coverage, licensing and reuse of existing locality parsing before implementation. This approach adds no per-keystroke geocoding calls.

## Payment and database

The prefilled “Payment for [job]” text is an editable reference suggestion shown only when bank transfer is selected. The NZ bank account hint is an example of the account-number format. When the provider elects to share bank details and supplies both an account name and number, the optional details travel in the existing participant message. Confirmation can use “Arrange directly”. Payment acknowledgement and Undo remain optional and independent of completion or review eligibility. No payment processing or mandatory reference was added.

No database change is proposed. The existing RPC signatures, stored date and timestamp formats, schema, RLS and Marketplace Health scheduling are unchanged. Matching the exact long client format in a stored confirmation message would be a separate change to the existing database formatter.
